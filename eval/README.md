# Development scoring

The public scorer accepts an explicit schema-version-1 JSON packet with `split: dev` and a `methods` mapping using B0a, B0b, F1 and F2. Missing arms are always `not_yet_measured`. The hand oracle is authored arithmetic data, not a model result, public-PDF corpus, human gold or independent acceptance.

Each method supplies `origin` (`hand_oracle` or `development`), an inventory with `gold_atoms`, `predicted_atoms` and explicit `equivalence_edges`, plus optional retrieval, citation and abstention cases. IDs are stable. Admissible equivalence edges must be human-adjudicated; span overlap alone cannot create one. A deterministic maximum-cardinality match permits each gold/predicted atom once. Extra duplicate predictions reduce precision. Zero denominators are JSON null (N/A), including an all-abstain system's citation precision.

Retrieval is macro recall@10 and MRR@10 with no-evidence cases excluded and counted. Sentence/window citation pairs retain separate human semantic support and literal resolver judgments. Absent and conflicting abstention precision/coverage are separate; unavailable states do not become successful absence. Mandatory misses list the exact ID, page and clause. Wilson intervals identify item proportions and carry an independence caveat; macro retrieval does not receive a fabricated binomial interval. A bounded seeded whole-family bootstrap reports recall intervals from supplied labels only when at least three families exist; fewer families yield N/A, and fewer than six retains an explicit instability warning.

Optional `dataset_summary` reports the selected full/preliminary count floors and supplied rights/split/human/custody prerequisites without authenticating them. Full count eligibility requires 12 documents/6 families/180 atoms/60 mandatory overall, 6 development documents/3 families, and held-out 6 documents/3 unseen families/90 atoms/30 mandatory/20 absent/10 conflict/20 conditional-admin cases. Preliminary count eligibility requires 4 held-out documents/3 unseen families/60 atoms/20 mandatory/10 absent/5 conflict with conditional/admin slice counts present; it never becomes full acceptance. JSON null means missing evidence. The public helper accepts a sanitized mapping supplied later by an independent custodian; no private-label discovery or custody creation occurs.

After runtime validation is authorized, the intended command is `rfp-matrix eval --input eval/hand-oracle.v1.json --out <new-result-path>`. No command or scorer execution was performed during Dirty Mode construction. The scorer has no file-discovery logic, network calls or access to held-out labels; the CLI accepts development packets only.

The separate [prospective runner](RUNNER.md) now supplies source-only frozen comparison and injected fake-port dispatch contracts. It rejects changed raw inputs/configuration and requires an external authorize-and-consume custodian before dispatch. It does not implement independent custody, authorize live execution or expose held-out CLI scoring. [Corpus workflow](CORPUS-WORKFLOW.md) and `corpus.schema.json` define rights/family/annotation intake contracts without actual documents, human labels or custody records. All four comparison arms remain unmeasured. A real isolated confirmatory scoring host and human roles must be supplied and verified before quality claims.
